## 1. 评审结论

现有物料能够支撑课程概念里的三层架构：毫米波雷达负责空间引导，PCA9685 把舵机 PWM 从 Linux 调度里拆出去，树莓派做视觉确认与 MQTT，云端只在事件发生后收遥测和告警。按键、交通灯和 OLED 补上了概念文档里没有展开的本地人机接口，适合无头运行。

下面几项会直接决定 250 ms、0.5° 和 95% 这三条指标能不能测出来，建议在接线之前定下来。

1. **雷达固定在世界坐标系，摄像头装在云台上。** HLK-LD2450 给出的是相对雷达自身的 X, Y。雷达若跟着云台转，每一帧坐标都会叠上转角，跟踪环会正反馈振荡。雷达与云台水平轴尽量同轴、同向、靠近安装，只保留一个固定的安装偏角，在软件里做成标定常量。
2. **雷达没有高度维，俯仰不能只靠 \arctan(X/Y)。** LD2450 是平面 1T2R，只输出水平面坐标和径向速度。Pan 由方位角前馈；Tilt 先用“安装高度 + 假定人体高度”做几何俯仰，人脸进入画面后再用视觉伺服修正。
3. **两路 5 V 必须在 PCA9685 端子处与树莓派共地，舵机电流不要进面包板。** 充电宝 C 口供树莓派、A 口供舵机，这个拆分是对的。PWM 和 I2C 仍以树莓派地为参考，伺服地和逻辑地要单点相连。MB-102 只走信号线（I2C、按键、LED、舵机信号）。
4. **PCA9685 的逻辑电源接 3.3 V，舵机电源只接绿色端子 V+。** 逻辑端若接 5 V，板上拉会把 SDA/SCL 拉到 5 V，树莓派 GPIO 不耐 5 V。清单里已经按 3.3 V 逻辑写了，接线时保持这一点。
5. **250 ms 只覆盖“雷达帧 → 云台粗对准”，不覆盖人脸识别。** MG90S 空载大约 0.1 s/60°。大角度加上摄像头负载后，机械到位可能超过 250 ms。验收时把指标拆成：软件出脉宽的时间，以及转角不超过约 30° 时的机械到位时间。
6. **0.5° 是 PWM 量化的理论上限，MG90S 死区往往更大。** 50 Hz、12 bit 时 1 个 LSB 约 4.88 µs，对应大约 0.44°。舵机死区常见数微秒到十余微秒，实测稳态分辨率更可能在 1° 左右。报告里应同时给出理论分辨率和实测死区。
7. **身份比对用这颗 5MP 摄像头做，但只在人走到约 2 m 以内、云台已经把脸移到画面中央之后做。** 限制不是总像素不够，而是 2.8 mm、约 100° 视场把像素摊到太宽的场景上。5 m 处两眼之间大约只有 20 像素，检测够用，比对不够。同一颗摄像头在 2 m 处大约有 45–60 像素的眼距，可以做家庭白名单比对。5 m 仍只做入侵检测，不宣称认出是谁。
8. **告警通道做成可替换接口。** WhatsApp Cloud API 需要 Meta 商业账号和消息模板审核，课程演示有被卡住的风险。MQTT 事件格式固定，通知端先留 Telegram 或 ntfy，WhatsApp 作为正式实现。

## 3. 系统架构

系统分四块。概念文档的三层保留，本地人机从边缘层里单独画出来，因为按键和灯不经过云。

```text
                    +---------------- 本地人机 ----------------+
                    |  K1..K4          OLED           R/Y/G   |
                    +----+--------------+---------------+-----+
                         | GPIO         | I2C           | GPIO
+----------+   UART      |              |               |
| LD2450   |-----------> |         Raspberry Pi 4B      |
| 雷达     |  256000     |    跟踪 / 视觉 / 状态机 / MQTT |
+----------+             +------+---------------+-------+
                                | I2C            | USB UVC
                         +------+------+         |
                         |  PCA9685    |         v
                         |  50 Hz PWM  |    2K USB 摄像头
                         +------+------+         ^
                           Pan / Tilt            | 机械指向
                         MG90S 云台 -------------+

Pi --Wi-Fi/TLS--> Mosquitto (OCI) --> 时序/日志
                       | 事件
                       +--> 通知（WhatsApp / 备用通道）--> 手机
```

数据流按“先空间、后图像、再告警”：

1. 雷达约 10 Hz 输出最多 3 个目标的 X, Y, v_r。
2. 跟踪器做关联，选出一个主目标，换算 Pan/Tilt。
3. PCA9685 更新两路脉宽，云台转向该方位。
4. 仅在已锁定或按下 K4 时跑人脸/人体检测。检测框中心偏离画面中心时，给云台一个小修正量。
5. 状态机确认入侵后，抓一张 JPEG，经 TLS 把事件 JSON 发给 MQTT，再由云端推送到手机。

边缘侧在断网时仍完成探测、转向、亮灯和 OLED 显示。云是告警通道，不是控制闭环的一部分。

## 4. 硬件接口与引脚

### 4.1 总线与地址


| 器件                   | 总线         | 地址 / 设备节点                 | 备注                            |
| -------------------- | ---------- | ------------------------- | ----------------------------- |
| HLK-LD2450 + USB-TTL | USB 串口     | `/dev/ttyUSB0`，256000 8N1 | 不占用 GPIO14/15，调试串口仍留给系统控制台    |
| PCA9685A             | I2C-1      | `0x40`（默认）                | SDA = GPIO2，SCL = GPIO3       |
| SSD1306 OLED         | I2C-1      | `0x3C`（部分模块为 `0x3D`）      | 与 PCA9685 并联，地址不冲突            |
| USB 摄像头              | UVC / V4L2 | `/dev/video0`             | 采集用 MJPEG，不做 YUYV 2K 全分辨率实时推理 |


上电后用 `i2cdetect -y 1` 确认两个地址同时出现。两块板若都带上拉，并联后上拉变强，400 kHz 一般仍可用；若总线不稳，把速率降到 100 kHz。

USB 转 TTL 优先使用 CH340 或 CP2102。部分仿冒 PL2303 无法稳定打开 256000。

### 4.2 GPIO 分配

避开 I2C（GPIO2/3）和串口控制台（GPIO14/15）。


| 功能            | BCM 编号 | 方向      | 有效电平   |
| ------------- | ------ | ------- | ------ |
| K1 布防/撤防      | GPIO17 | 输入，内部上拉 | 低电平    |
| K2 OLED 翻页    | GPIO27 | 输入，内部上拉 | 低电平    |
| K3 云台归中       | GPIO22 | 输入，内部上拉 | 低电平    |
| K4 强制抓拍       | GPIO23 | 输入，内部上拉 | 低电平    |
| 绿灯 待机         | GPIO5  | 输出      | 高亮     |
| 黄灯 锁定         | GPIO6  | 输出      | 高亮     |
| 红灯 告警         | GPIO13 | 输出      | 高亮     |
| 按键公共端、LED 公共端 | 任意 GND | —       | 与树莓派共地 |


按键软件消抖 30 ms。交通灯模块若为共阳（低电平点亮），在驱动层取反，应用层仍按“高 = 亮”的语义写。单脚电流控制在 8 mA 以内，三路合计留在树莓派 GPIO 总电流预算内。

### 4.3 舵机通道


| PCA9685 通道 | 机构      | 脉宽（初值，需标定）           |
| ---------- | ------- | -------------------- |
| 通道 0       | Pan 水平  | 中位 1500 µs；机械限位内再测两端 |
| 通道 1       | Tilt 俯仰 | 中位 1500 µs           |
| 通道 2–15    | 空       | 不输出                  |


软件限位建议先收到 Pan \pm 70^\circ、Tilt \pm 25^\circ，在云台还没顶到机械止档时就停。顶死会导致 MG90S 堵转，电流升高、齿轮发热。

PWM 频率 50 Hz。25 MHz 标称时钟下预分频：


\text{prescale} = \mathrm{round}\left(\frac{25\times 10^6}{4096 \times 50}\right) - 1 = 121


克隆板内部振荡器常有百分之几的偏差，1500 µs 的实际脉宽会偏。联调时以舵机机械中位为准，在软件里加一个脉宽偏移，不依赖晶振标称值。

12 bit、20 ms 周期时：


1\ \text{LSB} \approx \frac{20\text{ms}}{4096} \approx 4.88\ \mu\text{s}


若有效脉宽跨度按 1000 µs 对应 90° 估算，角度量化约为 0.44^\circ/\text{LSB}，满足“步进 < 0.5°”的理论口径。报告中同时记录：逻辑分析仪上的脉宽步进，以及舵机实际会动的最小角度。

## 5. 电气与机械约束

### 5.1 电源


| 负载                         | 供电                              | 说明                         |
| -------------------------- | ------------------------------- | -------------------------- |
| 树莓派 4B、雷达 USB-TTL、摄像头、OLED | 充电宝 C 口 → 树莓派 Type-C            | 雷达和摄像头从树莓派 USB 取电          |
| MG90S × 2                  | 充电宝 A 口 → PCA9685 绿色端子 V+ / GND | 与树莓派 5 V 分开，避免启动瞬态把 Pi 拉重启 |
| PCA9685 逻辑 VCC             | 树莓派 3.3 V                       | 保证 I2C 电平为 3.3 V           |
| 共地                         | Pi GND 与端子 GND 一根线单点连接          | 给 PWM 信号提供回流               |


两只 MG90S 堵转合计大约 1–1.5 A。A 口 3 A 容量足够。PCA9685 端子旁加 470–1000 µF 电解电容，吸收换向电流。这路大电流用杜邦线直达端子，不经过 MB-102。

### 5.2 机械安装

- 雷达安装高度建议 1.2–1.5 m，前方 6 m 内避免大面积金属板。金属会形成多径，坐标会跳。
- 雷达与云台固定在同一刚性基板上。泡沫只做减震垫，不作为雷达的角度基准；泡沫形变会让标定角慢慢漂。
- 云台转动时的振动会传到雷达。基板分开固定，或在雷达支架与云台之间留开。
- 摄像头光轴与雷达法线在云台归中时对齐，偏差记入 \theta_0, \varphi_0。

### 5.3 传感几何

LD2450 典型工作区：方位约 \pm 60^\circ（合计 120^\circ），距离约 6 m，同时最多 3 个目标。摄像头瞬时视场约 100^\circ，但只有云台转到雷达所指方向后，目标才落在画面里。系统覆盖角由雷达视场和云台机械行程共同决定，不由镜头单独决定。

5 m 处、水平视场 100^\circ 时，画面覆盖宽度约：


W = 2 \times 5 \times \tan(50^\circ) \approx 11.9\ \text{m}


身份比对看的是两眼间距占多少像素，不是传感器标称 500 万。成人瞳距约 63 mm。水平视场按 100^\circ、画面宽按 2592（5MP 宽边）估算：


\text{眼距像素} \approx 2592 \times \frac{2\arctan(0.0315/r)}{100^\circ}



| 距离    | 约略眼距像素（2592 宽） | 用途           |
| ----- | -------------- | ------------ |
| 5 m   | 约 19 px        | 人脸/人体检测、云台跟踪 |
| 3 m   | 约 31 px        | 检测稳定，比对仍偏松   |
| 2 m   | 约 47 px        | 白名单比对的起始距离   |
| 1.5 m | 约 62 px        | 比对比较稳        |


常见可用门槛是眼距不少于约 40 像素，且脸基本正对、没有运动模糊。所以比对触发距离先定为雷达 r \le 2\text{m}，联调时用实拍眼距再改。若 UVC 实际只输出 1920 宽，同一距离的眼距大约少三分之一，触发距离收到约 1.5 m。

把 720p 画面放大不能增加眼距像素。500 万像素只有在比对那一帧真正采到全分辨率时才算数。

## 6. 软件结构与技术选型

运行环境：Raspberry Pi OS Bookworm 64 位，Python 3。无桌面，systemd 拉起主进程。


| 层次   | 选型                                            | 用途                            |
| ---- | --------------------------------------------- | ----------------------------- |
| 串口   | `pyserial`                                    | 读取 LD2450                     |
| GPIO | `gpiozero` + `lgpio`                          | Bookworm 上用这套，避开已过时的 RPi.GPIO |
| PWM  | `adafruit-circuitpython-pca9685` 或直接 `smbus2` | 写 50 Hz 脉宽                    |
| OLED | `luma.oled`                                   | SSD1306 128×64                |
| 视觉   | OpenCV（V4L2，MJPEG）+ YuNet + SFace             | 720p 检测跟踪；近距离全分辨率身份比对，见 7.6   |
| 消息   | `paho-mqtt`，TLS                               | 连接 OCI 上的 Mosquitto           |
| 日志   | 本地 JSONL，云端 InfluxDB 或同等时序库                   | 概念图中的 logging engine          |
| 进程管理 | systemd                                       | 上电自启、崩溃重启                     |


线程划分：


| 线程    | 周期           | 职责                 |
| ----- | ------------ | ------------------ |
| 雷达接收  | 阻塞读，约 10 Hz  | 拆帧，写入最新目标快照        |
| 引导与舵机 | 50 Hz        | 读跟踪结果，限速，写 PCA9685 |
| 视觉    | 有目标时约 10 fps | 检测，输出框中心误差         |
| MQTT  | 网络回调         | 心跳、事件、断线重连         |
| 人机    | 20 Hz        | 按键、灯、OLED 翻页       |


共享状态（主目标、云台角、系统状态）用一把锁。视觉线程不要直接写 PWM，只提交像素误差，由引导线程合并成角度指令。这样舵机更新率稳定，也不会被检测耗时堵住。

摄像头策略：布防后就以 1280×720 MJPEG、约 15 fps 打开设备，检测器只在“雷达已锁定”或 K4 按下时跑。临时打开摄像头常常要几百毫秒，会吃掉 250 ms 指标；平时不跑检测，则把 CPU 留给跟踪。

## 7. 算法

### 7.1 雷达帧解析

LD2450 工程输出为二进制帧，波特率 256000，8N1。社区与手册中常用的目标帧如下，**第一天上电要用串口原始字节核对**，不同固件的单位和符号位有过差异。


| 字段     | 内容            |
| ------ | ------------- |
| 帧头     | `AA FF 03 00` |
| 帧内长度   | 2 字节，小端       |
| 目标 1–3 | 各 8 字节        |
| 帧尾     | `55 CC`       |


单个目标 8 字节，小端：


| 偏移  | 类型     | 含义                  |
| --- | ------ | ------------------- |
| 0–1 | int16  | X，毫米，右为正（以手册符号为准）   |
| 2–3 | int16  | Y，毫米，前方为正           |
| 4–5 | int16  | 径向速度，厘米/秒；符号表示靠近或远离 |
| 6–7 | uint16 | 距离分辨率，毫米            |


解析器用状态机，不按“读固定长度”硬切，避免 USB 分包把帧从中间切开：

1. 滑动匹配 4 字节帧头。
2. 读长度，长度超出 3 个目标的合理上限则丢弃并重新找头。
3. 收齐载荷和帧尾 `55 CC` 后提交。
4. 坐标全 0 或超出 \pm 60^\circ、6 m 的点记为无效目标。

配置帧（划定探测区域、重启模块）使用另一套帧头 `FD FC FB FA`、帧尾 `04 03 02 01`。正常跟踪不需要周期性配置；区域屏蔽（例如忽略正后方）可以在初始化时写一次。

### 7.2 坐标到云台角

雷达平面坐标换成方位角和距离。用 `atan2`，这样左右和背后的符号不会在 Y \le 0 时出错：


\theta = \operatorname{atan2}(X, Y), \qquad r = \sqrt{X^2 + Y^2}


\theta = 0 表示目标在雷达正前方。概念文档中的 \theta = \arctan(X/Y) 与此等价的前提是 Y > 0 且已处理符号。

俯仰用安装几何，而不是雷达测量。设雷达/云台光轴高度为 h_s，希望对准的身体高度为 h_t（胸部约 1.2 m，或面部约 1.5 m）：


\varphi = \operatorname{atan2}(h_t - h_s,\ r)


再加上归中标定：


\theta_{\text{pan}} = \theta + \theta_0, \qquad \varphi_{\text{tilt}} = \varphi + \varphi_0


然后钳位到软件限位，再映射到脉宽。映射在标定时用两端实测脉宽线性插值，不使用未测量的“500–2500 µs = 180°”。

### 7.3 多目标关联

模块最多给 3 个目标，且帧与帧之间没有稳定 ID，顺序通常按距离而不是按人。需要自己维持航迹。

每一帧：

1. 丢掉无效点。
2. 用最近邻把量测配到已有航迹。门限可用 0.6 m（10 Hz 下人的帧间位移通常更小）。代价是平面距离。
3. 没配上的量测新建航迹；连续 5 帧（约 0.5 s）没有量测的航迹删除。
4. 主目标选择：已确认航迹里，优先“正在靠近且距离最小”的一条。切换主目标时加滞回，避免两个人距离接近时云台来回甩。

航迹滤波用二维常速度卡尔曼，状态 [x, y, v_x, v_y]^\top。雷达只提供位置和径向速度，径向速度作标量观测会引入额外投影，第一版可以只用位置更新，过程噪声按人的步行加速度来设（约 1\ \text{m/s}^2 量级）。10 Hz 更新足够平滑云台指令。云台跟随的是滤波后的 \theta, \varphi，不是原始跳点。

### 7.4 舵机引导：前馈加视觉修正

总指令：


u_{\text{pan}} = \theta_{\text{pan}} + \Delta\theta_{\text{vis}}, \qquad
u_{\text{tilt}} = \varphi_{\text{tilt}} + \Delta\varphi_{\text{vis}}


\Delta\theta_{\text{vis}} 默认是 0。画面里出现检测框之后：


e_u = u_{\text{box}} - u_{\text{center}}, \qquad
e_v = v_{\text{box}} - v_{\text{center}}



\Delta\theta_{\text{vis}} \leftarrow \mathrm{clamp}(\Delta\theta_{\text{vis}} + K_u e_u)


俯仰同理。K_u, K_v 用“像素误差 → 角度”的比例，先在 2 m 距离手调，使框中心能在约 1 s 内收到画面中央，且不来回过冲。

这是简化的基于图像的视觉伺服：默认目标在画面中心时云台就对准了它，用误差比例去修安装和高度假设的偏差。不做完整图像雅可比。

另外三条限制，用来满足“稳态无明显振荡”：

- **死区**：|e_u|、|e_v| 小于约 20 像素就不再积分，避免在检测框抖动上振荡。
- **角速度限制**：例如不超过 180^\circ/\text{s}，大阶跃时云台匀速转过去，而不是一帧打满脉宽。
- **指令低通**：引导线程 50 Hz 运行，对角度指令做一阶低通，截止大约 5–8 Hz，跟在雷达 10 Hz 之下。

课程里写的 PID，落在视觉修正这一级：P 对应 K_u，I 用来消掉安装偏角造成的固定像素残差，D 对 10 fps 的检测噪声很敏感，增益先放小，振荡就关掉 D。雷达方位本身用前馈，不放进同一个 PID 里重复积分。

### 7.5 告警逻辑

灯色和状态绑定：


| 状态   | 灯          | 进入条件                                | 行为                         |
| ---- | ---------- | ----------------------------------- | -------------------------- |
| 撤防   | 全灭         | K1 撤防                               | 雷达可显示，不转云台、不告警             |
| 布防空闲 | 绿          | K1 布防且无确认航迹                         | 雷达运行，云台保持                  |
| 锁定   | 黄          | 主航迹连续存在 ≥ 0.5 s                     | 云台跟踪；打开检测                  |
| 告警   | 红          | 锁定后检测到人脸或人体，且（距离仍大于比对门限，或比对结果不是白名单） | 抓拍一次，发 MQTT 事件；同一目标冷却 30 s |
| 已知人员 | 绿闪一次后回到绿或黄 | r \le 2\text{m}、脸已对中，特征和白名单相似度超过阈值  | OLED 显示姓名；不推送告警            |
| 抓拍   | 红闪一下       | K4                                  | 无论是否告警，存一张图并上报             |


误报抑制用“M 帧里至少 N 帧”：例如最近 10 帧里至少 7 帧有航迹，才从绿变黄。风扇和窗帘造成的零星点到不了 N。视觉确认是第二道门，黄灯可以跟踪，红灯必须过视觉或非常明确的接近轨迹。宠物误报要在测试里单列，LD2450 对小动物没有可靠的官方拒绝能力，不能假设雷达单独达到 95%。

### 7.6 视觉与身份比对

树莓派 4B 没有 NPU。检测和比对分成两条路径，避免全分辨率特征网络堵死云台闭环。


| 路径      | 何时跑      | 分辨率                     | 模型                             |
| ------- | -------- | ----------------------- | ------------------------------ |
| 检测与视觉伺服 | 雷达锁定后持续跑 | 1280×720 MJPEG，约 10 fps | OpenCV YuNet，只取框和 5 点          |
| 身份比对    | 每条航迹最多几次 | 摄像头能给出的最大 MJPEG（优先 5MP） | 同一 YuNet 对齐后，SFace 出特征，和本地白名单比 |


人体检测（小型 SSD）只作为补充：人已经进画面但脸还没正对时，仍允许从黄灯进入“有人”，身份标成未知。Haar 只留作对照。

比对是家庭白名单，不是认出任意陌生人是谁。库里每个人事先用这颗摄像头录入约 5 张正脸，保存特征向量的平均值。运行时取和库中最高的一条余弦相似度：

- 高于阈值：已知人员，记下姓名，不推送手机告警。
- 低于阈值，或脸太小、侧得太多、云台还在转：未知。人已经在范围内则按入侵告警。

阈值用留出的照片在本机标定，宁可把家人偶尔判成未知（多一次告警），也不要把陌生人判成家人。OpenCV 自带 SFace 示例的余弦阈值大约在 0.36 附近，只能当起点，以本摄像头、本房间的实测为准。

一次比对的准入条件同时满足才抓全分辨率帧：

1. 雷达距离 r \le 2\text{m}（实拍眼距不够 40 像素就把门限改近）。
2. 720p 里脸框已经靠近画面中心，云台角速度接近 0，并保持约 200 ms，避免运动模糊。
3. YuNet 置信度足够，两眼和鼻子的 5 点表明脸大致正对镜头。

特征不每帧都算。Pi 4 上 SFace 一次前向大约一百到几百毫秒，一条航迹在距离门限内算一次，相似度不够再隔 0.5 s 重试，最多 3 次。云台跟踪始终用 720p 检测，不等这条结果。

采集注意：很多标称 500 万的 USB 模组在 UVC 里只列出 1080p 或 2K。上电后先看 `v4l2-ctl --list-formats-ext`。比对帧用列表里最大的 MJPEG；跟踪帧保持 720p。临时切换分辨率时云台可以停在当前角，人已经在 2 m 内，短暂停顿不影响 250 ms 的粗对准指标。

录入不占用 K1–K4，用单独脚本在同一颗摄像头、1–2 m、室内灯光下完成。特征向量只留在树莓派上。上传云端的告警图仅来自未知人员。

若以后确实要在 5 m 认出人，换更长焦距的镜头（模组若是 M12 接口，大约 8 mm 能把 5 m 眼距提高到约 50 像素），同时云台必须更准，因为视场会从约 100° 收到大约 40°。当前阶段不换镜头，用“远处检测、近处比对”。

抓拍：未知告警时把该帧编码 JPEG，质量约 70，长边 1280。图片不进持续视频流。

### 7.7 时延预算（对准 250 ms）

这条指标的路径是雷达帧到云台机械到位，不含检测和上传。


| 环节                  | 预期                          |
| ------------------- | --------------------------- |
| 雷达帧周期               | 100 ms（10 Hz），平均等待半帧约 50 ms |
| 串口解析 + 跟踪 + I2C 写脉宽 | < 15 ms                     |
| MG90S 机械，约 30° 负载转动 | 80–200 ms，需实测               |
| 合计（30° 以内）          | 目标落在 250 ms 内               |


转角更大时，单独报“到位时间”和“每度平均时间”，不把 90° 大甩和 250 ms 绑在同一条判据上。测量方法：GPIO 在“帧解析完成”时翻转，舵机摇臂上贴标记，用手机慢动作或第二个摄像头记时；有条件时用逻辑分析仪看 PWM 变化沿。

## 8. 通信与云

### 8.1 MQTT

Broker：OCI 上的 Mosquitto，端口 8883，TLS。树莓派使用客户端证书或用户名密码，二选一，证书文件权限收紧。断线指数退避重连。心跳主题每 10 s 一次，OLED 根据最近一次 CONNACK 和心跳显示在线/离线。

主题建议：


| 主题                 | 方向     | 内容                                        |
| ------------------ | ------ | ----------------------------------------- |
| `home/<id>/status` | 设备 → 云 | 布防状态、云台角、IP，保留消息                          |
| `home/<id>/track`  | 设备 → 云 | 主目标 x, y, v_r, \theta，最多 2 Hz，避免 10 Hz 灌满 |
| `home/<id>/event`  | 设备 → 云 | 告警 JSON：时间、坐标、状态、图片 URL 或小图               |
| `home/<id>/cmd`    | 云 → 设备 | 远程布防/撤防、归中。本地 K1 与远程命令进同一个状态机             |


事件 JSON 只放元数据和小图引用。原视频不上传。

### 8.2 图片与通知

WhatsApp Cloud API 发图片通常要一个 HTTPS 可访问的地址。路径可以是：树莓派把 JPEG POST 到 OCI 上的一个很小的接收程序，程序落盘后由 Mosquitto 的 webhook 或同一程序调用通知接口。

通知接口做成一个函数：输入事件 JSON，输出“已发送/失败”。WhatsApp 是目标实现；Telegram Bot 或 ntfy 用同一 JSON，方便在没有 Meta 商业审核时把演示跑通。

传输加密用 TLS。若作业明确要求“本地加密后再上传”，对 JPEG 做 AES-GCM，密钥放在设备上，云端接收程序解密后再交给通知通道。密钥不要写进仓库。

### 8.3 时序库

概念图中的 logging engine 用 InfluxDB 接收 `track` 与 `event`，用来画轨迹和统计误报。若部署时间不够，先在 VPS 上把 MQTT 消息追加到日志文件，指标统计用离线脚本完成，接口形状保持一致。

## 11. 实施顺序

按这个顺序做，每一阶段都有可以演示的结果，避免最后一起联调。

1. **电源与共地**：Pi 与舵机分路供电，共地，电容焊上。空载转舵机，确认 Pi 不重启。
2. **I2C**：`i2cdetect` 看到 `0x3c` 和 `0x40`。OLED 打出 IP。PCA9685 使舵机归中。
3. **雷达**：打印 X, Y, v_r，用卷尺核对单位和坐标方向（左/右、前）。
4. **开环指向**：人站定，云台转到 \operatorname{atan2}(X,Y)。记下 \theta_0, \varphi_0 和脉宽两端。
5. **跟踪**：最近邻 + 主目标选择 + 角速度限制。多人从雷达前走过，云台不来回抖。
6. **视觉**：720p 检测框，像素误差修云台。确认 5 m 处框还在。
7. **身份比对**：确认 UVC 最大分辨率，录入白名单，只在约 2 m 内做 SFace。用 T9 标定阈值。
8. **状态机与按键灯**：四键、三色灯、已知人员不推送、冷却时间。
9. **MQTT 与通知**：先备用通道，再接 WhatsApp。断网重连。已知人员事件不发告警图。
10. **指标测试**：按第 10 节记录数据，写进报告。

## 13. 建议写入课程报告的技术要点

报告后续章节可以直接展开下面几条，它们和概念文档的公式、架构图一致，也和现有物料一致。

- 方位解算 \theta = \operatorname{atan2}(X, Y)，以及俯仰的几何模型 \varphi = \operatorname{atan2}(h_t - h_s, r)。
- 雷达前馈与视觉伺服修正分开，PID 只作用在像素误差上。
- 无稳定 ID 时的最近邻关联，以及可选的常速度卡尔曼。
- PCA9685 把 50 Hz PWM 从 Linux 调度中卸掉；给出 LSB 与 0.5° 的计算，再用实测死区修正结论。
- 事件驱动：10 Hz 雷达在本地消化，云端只收心跳、降频轨迹和告警图。
- 真阳性 95% 的实验协议（样本量、距离、阴性对照）。
- 身份比对与检测分开：5 m 看眼距像素不够，约 2 m 用 YuNet 对齐加 SFace 白名单；阈值用本摄像头标定。

第一版软件不必上完整卡尔曼和 AES。雷达解析、角度前馈、PCA9685、状态机和 MQTT 心跳接通之后，系统就已经覆盖概念文档的主路径。视觉修正、多目标关联和 WhatsApp 按第 11 节往上加。
